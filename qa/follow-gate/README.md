# 本地提词跟踪 + Jev 跟读开关（试用版）

按用户最新要求撤掉未交付的“模型选择句子/位置”方案。正式页面改用 `Teleprompter` 和 `FollowGate` 两个独立模块：

- `Teleprompter` 接收 ASR 转写，在本地进行连续文字对齐、短语回读与局部模糊匹配。它不读取任何模型概率，只生成文本位置。
- `FollowGate` 只接受一个 Noul 概率：讲者是否仍在朗读或以近义表达复述稿件。模型请求里没有位置选项；模型响应也没有位置字段。
- 已处于跟读状态时，本地强匹配直接更新。Jev 在旁路异步监听；明确判为插话时关闭开关，画面留在当时位置，不回滚。恢复跟读后继续使用本地候选位置。
- 概率 ≥ 0.65 开启，≤ 0.35 关闭，中间区域维持上一次状态，避免不确定片段导致频繁开关。这是演示阈值，不是概率已校准的承诺。首次尚无判断时，只预览当前位置附近的强匹配。
- 语义模糊候选等待肯定的跟读状态；对应位置仍由本地算法提出，以片段高亮显示，不伪装成字级声学对齐。
- 可点击任意稿件行指定起点，也支持键盘 Enter/空格。点击会使旧结果失效；如果麦克风仍在工作，同一 ASR 段里点击前已经识别的前缀不再参与定位。

## 验证

`npm test` 105 项通过，`npm run build` 通过。新测试证明本地定位不需要模型结果、模型不能提供坐标、暂停不倒退、旧返回失效、模糊判断保持前态、点击定位隔离旧音频、正常累积前缀不产生假确认。

`scripts/benchmark-follow-gate.ts` 真实调用 Jev，只发送 `following` 一个 Noul 问题。`live-jev.json` 保存完整输入与输出。正常朗读、错字、近义表达通过；“接下来我补充一下，大家有没有用过这种软件？”和含义相反的句子关闭开关。短语“接下来”返回 0.47，在此前处于跟读状态的测试条件下维持开启，本地定位回到位置 3；没有把 0.47 宣称成模型明确判定为跟读。

浏览器样本通过 AudioWorklet → 当前正式 ASR → 本地位置跟踪，同时真实调用 Jev：

- `browser-aside.json`：位置到 20；“下面先停……”时 Noul 降到 0.28、0.21 等，位置保持 20；恢复“然后继续”时达到 0.65，随后推进到 32。
- `browser-return.json`：第二句结束位置 34，跟读开关处于开启；“接下来”返回时本地位置直接变为 3，随后 Jev 的不确定结果没有把开关来回切换。
- 实测也暴露了 ASR 暂时将“我按稿”识别成“火案搞”的情况，Jev 会暂时暂停，直到后续转写明确后恢复。这仍可能造成短暂等待，不能保证现场麦克风、口音或噪声下无停顿。
- 实测后补充修复：精确累计前缀优先于其末尾短词，避免将普通连续朗读误记为多次重新定位；已加入回归测试。
- `manual-seek.json` / `manual-seek.png`：正式页面点击第二句，明确选中该句的第一个字。

音频测试使用合成样本，不是用户现场录音。只说一个含糊的转场词时，任何方法都无法提前知道接下来是回读还是插话；这版选择保持已有跟读状态，等待后续语音，而不重新引入模型选位置或逐句等待。
