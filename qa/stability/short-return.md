# 三字短语回读验收

用户复现：读到后面后反复说“接下来”，光标不返回，必须读较长片段才返回。

原因是代码门槛，不是 Jev 提示词：原局部短片段只在预计下一位置匹配；全文重新定位至少需要六个字，并要求稳定前缀、最终结果或继续增长的转写。“接下来”在调用 Jev 前就被过滤。

本次允许稿件中唯一出现的 3–5 字短语直接定位。输入必须是完整短语、重复短语、末尾独立分句或本次新增的短语，不从任意长插话里随便截取三个字。重复出现的短语以及孤立的两个字仍不直接触发远处跳转。缩短的同段 ASR 修订不当成主动回读；新的语音段和真实重复则可以返回。按一个词定位后，后续更完整的精确前缀允许向左扩展，避免被原来的起点锁住。

## 真实浏览器验证

使用 Windows 自带 Microsoft Huihui Desktop 合成 `public/fixtures/short-return.wav`（PCM16、16 kHz、单声道），内容：

> 我按稿件朗读，标记就跟随我的位置。
> 接下来。
> 接下来。
> 接下来，我用跟读场景演示这套流程。

中间各停顿 900 ms。通过 `/?audio-qa=return#voice` 进入，点击“播放样本音频”。音频经过浏览器 AudioWorklet、正式后端与 Qwen-Audio 3.1 ASR，再进入同一个稿件定位组件。没有把预置文字直接发送给定位回调；未采集用户麦克风。

观察到第二句确认位置 34；返回“接下”时保持 34；返回“接下来”（未有句号）时立即显示位置 3、状态“暂定 · 短词连续匹配”。随后重复两次保持 3，继续朗读时依次推进 7、10、13、16。证据为 `short-return-trace.json` 和 `short-return.png`。

还针对测试中出现的转写“我案搞件朗读”修正为“我按稿件朗读，标”补充了回归：词语定位后的完整前缀可以继续推进，不再被错误起点锁住。

自动测试覆盖三字 partial 立即返回、同段连续重复、无标点追加、句内回读、转写缩短、歧义短语、后续继续朗读；96 项测试及构建通过。字体、讲稿与正式 ASR 选择保持不变。

限制：仍要等 ASR 返回短语；不声称在声音到达前预测文字。
