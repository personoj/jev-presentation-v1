# 跟读定位稳定性与重新定位 · 2026-09-27

验收目标：高亮实际读到的位置；正常连续朗读不因转写修订来回抖动；插话保持当前高亮；明确重读前句或跳读后句时允许重新定位。

修复了两个直接问题：界面暂停时从暂定位置切回确认位置，以及短片段在较大搜索窗口内命中其他句子后立即移动。还加入了旧语音段结果的屏蔽，避免已经进入新句子后被旧结果改动。

最终实现并非永久禁止回退。当前句附近保持连续跟随；远处重新定位要求至少六字的唯一精确匹配，并有最终结果、云端稳定前缀或两个继续增长的转写片段支持。单纯标点变化不算第二份证据。累积转写夹有插话时，用最近的精确文字尾部恢复位置。短而重复的词不足以唯一确定位置时先保持，等待后续文字。

字形高亮和确认状态分开：插话、请求失败、转写缩短不会把已显示的标记切回较早的确认位置；在真实重读得到支持时才允许向前面的句子重新定位。非精确临时片段不再先移动再撤回，而是等待核对。

正式稿件从 35 字改为 72 字（含标点，不含换行），五行；字号 43 → 32，行高 46，全部放在原纸张区域内。

## 验证

- `npm test`：86 项通过；包括转写缩短、重复短语、旧段晚到、插话保持、跳读、回读、超出旧搜索窗口的回读、标点修订不触发跳转、同一语音段插话后恢复。
- `npm run build`：通过。
- 浏览器复现原回退条件：文字预览到位置 8、确认位置仍为 0 时立即插话。修复后仍显示 8，不跳回 0。此项是文字输入测试。
- 最新构建的真实云端音频测试：浏览器 AudioWorklet → 正式 Node 服务 → 千问 ASR → 页面，观察位置为 `2, 6, 10, 15, 17, 20, 20（暂停）, 24, 27, 28, 30, 32`。插话期间保持 20，最终确认 32。
- 不重置页面，重新播放同一份真实音频，验证从最后一句回读第一句：位置 `32 → 10`，第一句随后确认到 10。这次返回是新的朗读证据触发，不是旧结果回滚。
- 原始浏览器 DOM 采样见 `browser-evidence.json`。测试使用现有合成 WAV，不声称验证了用户现场麦克风、口音或噪声。
- `voice-long-script.png` 用于检查正式页面的五行稿件排版；截图中的固定文字按钮不作为云端识别证据。

目前高亮仍受云端文字返回速度影响；云端一次返回多个字时会定位到这一批文字的末尾，未伪造逐字声学时间戳。
