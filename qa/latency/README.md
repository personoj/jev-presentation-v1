# 跟读链路优化验收 · 2026-09-27

本次保留演示视觉，优化浏览器音频采集 → 本地 WebSocket → 千问流式 ASR → 稿件匹配 → Jev 差异核对 → 高亮的等待和重复工作。

## 改动

- PCM 上传由 100 ms 改为 40 ms 一包，停止时先发剩余音频再结束会话。
- 去掉每次转写都会重置的 800 ms Jev 防抖。一个请求进行中时仅保留最新待核对输入，启动间隔下限 250 ms；新文本不会反复取消健康请求。同文本由暂定转为最终时复用请求；过期结果不能更改新位置；请求 2500 ms 超时后释放队列。
- 当前位置开头精确对应的 2–3 字立即暂定高亮，不把短词当作确认，也不会在稿件别处搜索短词跳转。
- 云端稳定前缀只有在至少 6 字、精确对应稿件并通过位置限制时才提前确认。无关插话仍保持位置。
- 精确前缀走快速匹配，基线对照仅在最终结果计算。字形尺寸在字体加载、稿件变更和窗口变化时测量，声音电平变化不再触发全文几何测量。
- 限制浏览器和后端音频积压；网络异常时明确报错，不静默丢音频或积压几十秒。
- “转写与稿件”面板显示首段识别、更新间隔、本地匹配、Jev 请求和浏览器上传积压。

## 实测，不是按钮文字演示

`before-100ms.json` / `after-40ms.json` 使用同一份 12.65 秒合成 WAV，实时发送到真实云端 ASR。该测试经过 Node 后端，不经过浏览器音频处理器。

| 测量 | 100 ms 分包 | 40 ms 分包 |
|---|---:|---:|
| 首个文字距首包音频 | 441 ms | 469 ms |
| 有效文字更新间隔中位数 | 410 ms | 376 ms |
| 有效文字更新间隔 P95 | 964 ms | 916 ms |

两轮最终转写一致。单轮网络波动不能证明云端整体提速，首字也没有更快；本次主要收益来自应用不再额外等待。对同一份优化前事件记录，首个“我们”在 702 ms 返回，旧版最少四字门槛直到“我们使用”在 1623 ms 才满足，新的首次暂定位置可以提前 921 ms。这是这段样本的事件回放结果，不是所有语音的固定收益。

随后在 `http://127.0.0.1:4178/?audio-qa#voice` 点击“播放样本音频”，样本经浏览器 AudioBufferSource → 与麦克风共用的 AudioWorklet 重采样/分包 → 正式 4178 后端 → 真实云端 ASR → 页面高亮。没有把预置文本注入识别回调，也没有采集用户麦克风。

- 首轮：首段 ASR 455 ms；插话“下面先停一下”时位置保持 20，返回原文后确认到 32。
- 最终构建复测：首段 ASR 461 ms；首个两个字时 DOM 位置为 2、确认位置为 0；最终确认位置 32。最后一次本地匹配 0.4 ms，浏览器上传积压 0 ms。
- 证据：`browser-first-run.json`、`browser-final-run.json`、`browser-cloud-result.png`。
- 单独用“一处差异”的文本测试真实 Jev：将“转换”改为“转化”，返回 243 ms，确认位置 10，见 `browser-jev-review.json`。这项单独验证模型请求，不代表麦克风测量。
- `npm test`：75 项通过。覆盖队列不饿死、只保留最新输入、同文本最终结果复用、取消与超时、短词不跳转、音频尾包顺序、上传积压报错、ASR 稳定前缀与去重。`npm run build` 通过。

首段 ASR 指从第一包上传到第一段文字返回，包含样本前导静音，不是声学字级延迟。最近更新间隔也可能包含紧邻的修订事件，不代表持续吞吐率。实际麦克风、口音和现场噪声未实测；云端仍可能数百毫秒才返回一批文字，未使用猜字动画掩盖这个限制。

## 复现

1. `npm run build`，启动 `npm start`（4178 端口已有本项目服务时直接使用）。
2. 打开 `/?audio-qa#voice`，点击“播放样本音频”，展开“转写与稿件”。样本专门包含稿件以外的两段插话。
3. 后端独立测试：`node scripts/benchmark-asr.mjs repeat-40ms 40`。需要现有服务密钥，使用真实云端额度；输出到本目录。
4. 正式演示使用 `/#voice`，仍是用户麦克风和原有三行稿件。

协议依据：[千问客户端事件](https://help.aliyun.com/zh/model-studio/qwen-asr-realtime-client-events)、[千问服务端事件](https://help.aliyun.com/zh/model-studio/qwen-asr-realtime-server-events)。保留原有 400 ms 静音切分，不通过激进切句降低显示延迟。
